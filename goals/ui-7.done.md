## 1–4

- **Step state** renders every field of build-6's schema: goal, constraints, decisions with
  their reason, open steps with their next action, closed steps with outcome/`verified`/commit,
  the working set with per-file notes, `last_failure`, `hypothesis`, blockers, dead ends, and
  the evidence `seq`s on each entry. `seq` reads as **"caught up through record N"**, because
  hx owns the cursor and stamps `max(model, log head)`. A key a Companion adds inside an entry
  renders generically, since build-6 says entry keys are open.
- **The budget bar** is spec 10's chars/4, the same estimate `hx.stepstate.evict` uses.
- **Digests** from the Companion replace `_pending companion_`, on the stream card and in the
  subagents table; a test asserts the placeholder is gone.
- **`turn.background_tasks`** renders as "stopped with work still running" with the task ids.
- **The Agent error state** keeps the id switcher, names the id, and says whether the board
  still lists it — so an unknown id or a failed read is no longer a dead end.

**Against the real commands**, which is better and became possible mid-goal: build-7's cut

**`hx.companion.ingest`** — the function the Companion's own `stop` hook accepts a pass with.
A state hx would reject cannot be committed as a fixture.

`turn` is the one thing still unverifiable against hx: `hx show --json` does not carry it yet
(build-7). The header falls back to the board's `turn_ts`, and the rendering is tested against

## Three things worth flagging

1. **`hx archive --json` was broken** when I got to it: `src/hx/archive.py:96` still unpacked
   two values from `find_work_items`, which now returns one dict, so every call raised
   `AttributeError`. Reported in `handoff/ui-to-build.md`; the build lane fixed it the same
   day. The skip helper it prompted (`conftest.archive_is_broken`) stays — it costs nothing and
   turns a repeat into a skip with a name on it rather than a red ui suite.
2. **`state_budget_tokens` is not in `hx show --json`.** The used side of the bar is real; the
   budget is the `templates/worker` default of 10000 and is **labelled** as such. The UI will
   not read `config/<id>/harness.json` itself — everything else comes through the build lane's
   functions, and that rule is worth more than this bar being exact. Asked for; it needs a
   `CONTRACTS.md` line, so it is the orchestrator's call as much as the build lane's.
3. **The gtm packs were mid-cut** in three ways at once (an order with `after:` frontmatter, an
   `after` in `tasks.json`, and `packlib.State` narrowing while `STEPS` had not). All fixed on
   their side; the pack-driven tests now run again over all eleven observation points. They
   skip with a named reason rather than failing if it recurs.

## One correction

I first asserted the Orders view's ids equal the board's ids with a non-null `dispatched`.
They are not the same set: `hx orders` reads `tasks.json`, while the board's `dispatched` comes
from the work item's frontmatter, which `packlib` stamps on idle items too. Corrected to
compare against `tasks.json`, and told the gtm lane, since it is their pack that makes the
difference visible.
