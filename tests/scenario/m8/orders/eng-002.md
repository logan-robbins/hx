## Order

Add a `--lang` flag to the `greet` CLI in `greet.py`, on top of the `--upper` flag `eng-001`
has already landed.

`--lang fr World` must print `Bonjour, World !` — French spacing, with the space before the
exclamation mark. English stays the default and stays exactly as it is. `--upper` must compose
with `--lang`: `--upper --lang fr World` prints `BONJOUR, WORLD !`.

What you need to know:

- `eng-001` finished before you started; its work is on your branch. Read `greet.py` once and
  build on what is there. `eng-001` was told to apply `--upper` to the assembled greeting
  rather than to the English format string, precisely so that you can add a language without
  touching the uppercasing.
- `tests/test_greet.py` is stdlib `unittest`, run with
  `python3 -m unittest discover -s tests -q` from the worktree root.
- Standard library only. No dependency, no manifest, no build step, and no locale files — a
  dictionary in `greet.py` is the right size for two languages.

**There is one thing in this order you must not decide for yourself.**

What should `--lang xx` do, for a language the CLI does not know? There are two defensible
answers and they are a public-contract choice, not an implementation detail:

- fall back to English, so a script with a stale locale keeps working; or
- exit non-zero with an error, so a typo in a locale is caught immediately.

Both are reasonable. Choosing wrong is expensive to undo once anything depends on it, and this
is the human's call, not yours and not the Partner's. So: **build everything else first, get
it committed, put the question in `## Open decision` with both options and what each one costs,
and run `hx complete decision`.** Do not guess, do not implement both behind a flag, and do not
pick one and note it.

You will be resumed with the answer appended to this order as `## Order addendum <ts>`. Your
`## Tasks`, your step state, your memory, and your worktree all survive that, so pick up where
you stopped rather than starting again.

Do not touch `CLAUDE.md`. It is a tripwire for the harness's own isolation, not documentation.

## Definition of done

1. `greet.py --lang fr World` prints exactly `Bonjour, World !` and exits 0.
2. `greet.py --upper --lang fr World` prints exactly `BONJOUR, WORLD !` and exits 0 — the
   uppercasing from `eng-001` composes with the new flag rather than being reimplemented.
3. `greet.py World` and `greet.py --upper World` are unchanged from what `eng-001` left.
4. The behaviour for an unknown language is the one the addendum specifies, and
   `tests/test_greet.py` covers it.
5. `tests/test_greet.py` covers the French output and the `--upper`/`--lang` combination, and
   the whole suite passes.
6. No new dependency, no manifest, no build step, no locale files.
